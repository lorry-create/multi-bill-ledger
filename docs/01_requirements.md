# 产品需求和初赛交付

目标是帮助个人归集支付宝、微信账单，在修正识别和分类后得到可核对的月报，并让个人分类规则在下一笔交易中生效。11 月 19 日前交付大部分核心功能，11 月 20 日提交。

## 初赛范围

| 需求 | 必须交付 | 对应任务 |
| --- | --- | --- |
| F01 登录隔离 | 两个演示账号；账单、原图、规则、预算、导出都核验归属 | T00、T10 |
| F02 文件导入 | 支付宝、微信真实导出格式；总体支持 CSV 和 XLSX；写明支持格式版本 | T01、T02、T03 |

初赛不承诺模型训练、银行全接入、公开分享链接、账单 API 直连、高可用。RPA 为核心功能通过后的限定实验，不阻塞人工上传；RPA 文件上传、DeepSeek API 和 OCR API 不计作直接账单 API 加分。

## 用户流程

用户登录 → 上传文件或截图 → 等待解析和分类 → 对照原始内容修正 → 确认入账 → 查看月报和预算问题 → 修改分类并选择记住 → 新交易应用个人规则 → 报表刷新 → 导出。

演示必须用另一笔新交易验证个人规则。预算未来效果若由回放数据演示，应标注回放，不能声称真实消费已改善。只改一条数据库记录或只显示图表不构成完整验收。

## 与评分的关系

业务闭环 30 分由完整操作、状态和规则回流证明；功能质量 25 分由准确性和错误处理证明；架构部署 20 分由共同接口、隔离、数据保护、从零启动证明；文档 15 分由准确且不超过规定页数的材料证明；创新 AI 10 分由 OCR、分类和个性化反馈的实际作用证明。需求覆盖不等于已获得对应分数。

初赛材料包括不超过 10 页设计文档、技术数据时间可行性、初步验证证据、可运行源代码初版及真实提交历史。决赛不超过 15 页和 5 至 8 分钟视频的要求不能误写成初赛视频硬性要求。
