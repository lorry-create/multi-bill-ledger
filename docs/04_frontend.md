# 队友 A 前端开发任务书

目标是在 Vue 3 和 TypeScript 中把上传、确认、分类修正、报表、预算和导出串成一个用户流程。负责 frontend 及前端证据，不创建第二套数据库或另定接口。

先读 README、AGENTS、01、02、contracts/openapi.json，执行 06 中 T03、T07、T09。T00 与队长共同建立工程和运行脚本；依赖接口未就绪可用标明的合成样例，但必须保留接口适配层并在就绪后切换真实请求。

## 页面要求

| 页面 | 操作 | 必须处理的状态 |
| --- | --- | --- |
| 登录 | 登录、获取 me 和 CSRF、退出 | 失败、会话过期、回到登录 |
| 导入中心 | 选择平台和文件或截图、上传、显示批次 | 大小格式错误、处理进度、失败、重复 |
| 确认页 | 原图或来源、逐行字段、校验、去重、选择入账 | 缺时间金额流向不能确认，重复点击幂等，版本冲突刷新 |
| 账单页 | 日期类别平台方向筛选、分页、编辑、记住商户 | 加载、空数据、失败、筛选范围与导出一致 |
| 月报页 | 汇总、饼图、趋势、预算、明细跳转、PDF | 无前月数据不捏造环比，退款单列，0 预算不除以 0 |
| 规则页 | 列表、类别、来源、停用 | 仅本人规则，停用不声称改写历史 |

金额在 API 使用整数分，在显示层格式化为元；编辑时使用字符串到分的精确转换，避免浮点乘除造成错误。报表主数字不在浏览器再另算一套。统一类别代码和中文名，unknown 流向不能自动显示为支出。

所有写操作发送 X-CSRF-Token，按契约处理 401、404、409、422、503。确认请求保留 request_id；网络失败后同请求重试使用同一 ID 和内容，修改内容后使用新 ID。成功修改后重新获取报表，避免仅改页面文本。

## 必须交付给队长

- PR 说明当前任务 ID、契约版本、受影响页面、实际 typecheck、lint、build 结果。
- 受影响流程的操作步骤及合成截图，明确哪些已连真实后端、哪些仍是测试替身。
- 至少覆盖日期和类别筛选、金额编辑、重复确认、防过期覆盖和导出范围等有业务风险的交互验证。
- T09 与后端验证 PDF 中文与图表、CSV 字段和金额，不以下载按钮出现为完成。

禁止擅自改动 contracts、后端迁移、认证方案或根 CI。发现接口不够用时按 10 提交最小变更说明，不能只在前端添加后端没有返回的字段。

## 直接使用接口的方式

必读11逐接口手册和12页面调用表。T00创建web/src/api目录并运行tools/generate_contract_artifacts.py，自动得到client.generated.ts；F从此文件导入operationId同名函数。它处理同源Cookie、CSRF、FormData、查询参数、204和Blob；页面负责表单校验、轮询、版本冲突、显示和刷新。

不能手写另一套DTO，不能手工更改生成SDK。更改契约后重新生成；--check会核对已存在的前端API目录中的SDK。TypeScript的number本身不能保证整数，金额输入还需精确转换与校验，后端再次检查。
