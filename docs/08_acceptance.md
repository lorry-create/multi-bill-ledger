# 测试和功能验收

文档检查、模块测试、数据库集成、真实提供方验证、浏览器流程和干净部署分别报告，不能用其中一个替代全部。每份结果写提交 SHA、契约版本、环境、输入、预期、实际、运行命令和失败项。

## 自动检查分阶段启用

本包 Contract checks 执行基础链接与合成账本核对、OpenAPI标准校验、29例请求响应Schema校验、生成物漂移检查、SDK严格类型检查与fetch替身测试。它不执行真实应用，不连接真实平台，不能证明金额业务代码、会话安全或闭环正确。tools/check_contract.py自身仍只是基础检查，标准校验由tools/validate_examples.py执行。

App CI 模板以 .example 扩展名交付，不会自动运行。T00 在真实前后端工程、依赖和测试存在后核对并改名启用；缺少测试应失败，不允许 continue-on-error 或不存在就跳过。模板提供 PostgreSQL 测试库、后端测试和前端检查构建，不提供真实 API key。不得指向个人生产数据库。

T00 后应建立对共用类型和实际 FastAPI OpenAPI 输出的兼容性测试，核对路径、必填字段、枚举和状态码，避免只有设计契约而实现已漂移。具体模型与 SQL 测试不由本文的文档检查代替。

## 核心验收用例

| 编号 | 输入和操作 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 未登录查询；用户 B 访问 A 的账单、批次、规则、原图、导出 | 未登录拒绝；其他用户资源不泄露 |
| A02 | 两平台实际文件，人工核对条数金额 | 支持格式内准确，说明行和坏行明确处理 |
| A03 | 同文件二次导入、同确认重试、相同 request_id 改内容 | 不重复入账；改内容冲突；失败事务不部分入账 |
| A04 | 同商户同金额两笔合法交易、支付退款同订单号 | 不误删合法交易和退款；疑似重复让用户确认 |
| A05 | 真截图含缺金额、无年份、模糊或多笔 | 保留首次输出和问题；未确认不计报表，修正后可入账 |
| A06 | 同草稿分别走个人规则、通用规则、真实模型、故障 | 来源诚实、优先级正确、失败待确认、无伪成功 |
| A07 | 只改本笔，再选择记住分类，再导入另一笔新交易，最后停用 | 本笔操作不暗建规则；新交易命中；停用后不再命中；别人不受影响 |
| A08 | 两个旧新页面修改同记录；更改金额日期类别 | 旧版本被拒绝；新值、日志、索引和报表一致 |
| A09 | fixtures 合成账本 | I=10000，E=4200，R=500，净支出3700，差额6300，单位分 |
| A10 | 餐饮预算2000、购物预算1500；退款和0预算 | 餐饮净支出2500超500，购物净支出1200剩300，0预算不除零 |
| A11 | 月份类别筛选后导出；打开中文 PDF | 与页面范围数字一致；中文图表可读；CSV 不触发表格公式 |
| A12 | 重启中断批次、断网、模型限流、密钥错误 | 可解释、可恢复或明确失败，不永久处理中、不重入账 |
| A13 | 存储、日志、仓库、原图和备份检查 | 敏感内容按约定保护，密钥分离，恢复时密钥有效 |
| A14 | 干净 Linux 按指南启动并运行 A02、A05、A07、A09、A11 | 无个人开发路径依赖，数据库和规则重启后保留 |

fixtures 中数据全为合成，用于精确口径和故障测试。它不能证明支付宝或微信真实导出可解析，也不能产生 OCR 或真实模型准确率。真实实验单独有授权样本和人工真值。

## 指标口径

文件解析报告有效条数、成功、失败、重复和人工金额差额。OCR 报首次输出字段正确数和可评估字段总数，记录截图数与交易数；缺失和未知值按预先说明的规则处理。分类报告准确率、待确认率、样本数、规则与模型差异、耗时和用量。个人规则样例单列，不能把用户修正后的记录算作原模型准确。

内部初始优化目标为金额 OCR 至少 95%、日期 OCR 至少 90%、分类至少 85%，不属于比赛规定或当前实测。未达到时先保证人工修正闭环，再如实改进，不筛掉失败样本来提高数字。

## 缺陷级别和发布

P0 包括金额或统计错误、越权泄露、重复入账、主闭环中断、无法启动；修复后才合并或提交。P1 包括核心流程频繁失败、无法正确导出或规则不生效，应在冻结版本前解决。P2 为不阻断使用的排版或次要体验，可以记录后推迟。

同一功能应保存实际证据而非只写勾选。模板见 10。11 月 19 日把已验收提交、文档、配置和依赖锁定；11 月 20 日只处理提交与演示阻塞。

## 0.2版可执行契约检查

先安装tools/requirements-contract.txt，执行tools/validate_examples.py --self-test校验OpenAPI标准及29个成功/错误快照；tools/generate_contract_artifacts.py --check检查手册、SDK和Postman没有漂移。contracts/typecheck_examples.ts包含应被拒绝的错误字段和类型，和SDK一起执行TypeScript严格检查。

tools/test_browser_client.cjs在SDK编译为CommonJS后用Node内置测试运行，验证查询、Cookie请求配置、CSRF、上传、204、错误、状态和下载。测试使用fetch替身，不证明真实会话或后端功能。契约CI中已经列出完整命令；远端是否成功须看实际Actions。
