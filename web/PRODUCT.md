# 归账

帮助个人把微信、支付宝账单归集到同一本账中，对照原始内容修正识别与分类，再得到可核对的月报和预算信息。面向应用创新赛的个人账单管理项目。

## 用户与核心流程

作品验收以「账单采集 → OCR 或文件解析 → 自动分类 → 月报分析 → 用户修正 → 后续交易应用个人规则」为主线。每次改动核对受影响环节，确保用户可用原件和明细追溯报表数字，可按日期与类别查询，并能导出筛选账单或月报。

- 采集支持微信、支付宝的 CSV／XLSX 账单文件和 PNG／JPEG 截图。识别结果可核对、修正并确认。
- 月报展示收入构成、支出分类和每日走势。按类设置预算后，可从超支金额查到对应账单。明细支持 CSV、Excel，月报支持 PDF。
- 用户明确选择记住商户后，个人规则才应用到同平台的后续交易。账单原件、敏感字段、预算及规则内容按后端约定加密存储，查询所需的类别、月份等索引保留明文。
- 支付平台开放接口直连是可选加分项，手动上传、OCR 或模型分类均不能作为直连证据。

服务需要整理本人多平台收支的个人用户。用户登录后上传导出文件或交易截图，等待解析与分类，对照原件修正、处理重复提示，再确认入账。之后可筛选和修正账单、查看月报与预算、导出 CSV／PDF。

在导入确认时修正类别，可在入账完成页直接保存对应商户的规则。已入账账单也可单独修正并记住商户，个人规则可以停用。

## 产品边界

- 账号内的账单、原件、规则、预算与导出按用户隔离；演示数据明确标识为合成数据。
- 归集由用户上传文件或截图启动；平台 SVG 只标识来源，不代表官方合作或账单 API 直连。
- 初赛范围不包含公开注册、公开分享链接、银行全接入或高可用承诺。
- 月报只统计已确认交易，区分收入、毛支出、退款、净支出与收支差额；收支差额不等于银行余额。
- 预算反映类别当月净支出与额度，不以演示或回放声称真实消费已经改善。

## 品牌与体验

名称为“归账”。品牌标记为本项目原创 SVG，以来源汇入账本的方向表达归集。界面采用沉稳蓝白、SF／苹方系统字体、半透明导航与清晰正文。动效用于解释流程和反馈操作，并遵循系统的减少动态效果设置。视觉细则见 [DESIGN.md](DESIGN.md)。

产品范围和口径依据 [README](../README.md)、[产品需求](../docs/01_requirements.md) 与 [业务约定](../docs/02_contract.md)。实现与验证状态按对应证据维护；本文件不把初赛目标视为已上线交付。
